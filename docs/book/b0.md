# Building a full language: B0

B0 (`b0/`) is a complete statically typed language: about 1350 lines of grammar and Rust, plus a
prelude written in B0. This chapter walks through how it is built, as a model for a language of
your own. It assumes the [tutorial](../tutorial.md), which shows the same pieces on a small
language. B0's guide, [`b0/README.md`](../../b0/README.md), describes the language itself.

## The crate

```toml
[dependencies]
a0-diag.workspace = true
a0-syntax.workspace = true
a0-hir.workspace = true
a0-driver.workspace = true
```

These are covered by A0's compatibility promise (`docs/compatibility.md`), and nothing else is
needed; `b0/tests/public_api.rs` fails if B0 ever uses more. The command is the driver's:

```rust
fn main() -> ExitCode {
    Language::new("b0", |text, source| match b0::compile(text, source) {
        Ok(m) => Ok(Program::Hir(m)),
        Err(d) => Err(CompileError::Diagnostics(d)),
    })
    .grammar(b0::GRAMMAR)
    .modules(Modules::new("b0", b0::start, b0::compile_file))
    .repl_main("fn main() {\n{}}\n")
    .main()
}
```

`grammar` gives the language server its highlighting, outline and navigation; `modules` makes
programs of several files and packages (the driver finds the files through the grammar's
`@import` rule and compiles each into a module of one HIR builder); `repl_main` is the program the
REPL puts statements into.

## The grammar

`b0/b0.a0g` starts with its format version and tokens, then rules with fields:

```
grammar b0 version 1;
token INT /[0-9][0-9_]*/;
...
fn_decl @def(function) @scope
    = pub:"pub"? "fn" name:NAME ~ "expected a function name" type_params? "(" ~ "expected '('"
      (param ("," param)*)? ")" ~ "expected ')'" ("->" ret:type ~ "expected a type")?
      body:block ~ "expected '{'";
```

`~ "message"` makes what comes before it required once the rule has started, with that message;
`@def(function)` says the rule declares a function named by its `name` field and `@scope` that it
opens a scope, which is all the language server needs for outline, definitions, references and
rename. Expressions are one `@prec` table of operators, and every keyword is reserved, which is
why value structs are written `inline struct` (a keyword `value` would take a common name away
from programs).

## Building HIR by name

The compiler is one walk over the tree. B0 has no symbol tables and no type checker: the HIR
builder resolves names in the scopes the walk opens, infers and checks types, and reports errors
with spans the walk sets. A `let` statement is:

```rust
"let_stmt" => {
    let value = self.expr(self.field(node, "value"));
    let ty = match self.opt(node, "type") {
        Some(t) => self.ty(t),
        None => self.b.fresh_type(),
    };
    let name = self.field(node, "name");
    self.at(name);
    self.b.let_named(self.text(name), ty, value)
}
```

`fresh_type()` is a type to infer; `at(name)` makes what is built next point at the name, so a
type error or an unused-variable warning is reported there. Names are used the same way:
`self.b.name(text)` for a variable or function, `call_named(name, args)`, `assign_named(name,
value)`, `field_named(object, name)`, `method_call(receiver, name, args)`, `new_struct_named(s,
names, values)`. Each finds what the name means and checks it, now or when the module is finished
and every type is known.

Declarations come first, so that items can be used before they are declared: `program` declares
every struct, enum and interface, then their fields, variants, methods and the signatures of
functions, and only then compiles function bodies.

## Syntax that is not in the HIR

A language adds syntax by building it from HIR that exists. In B0:

- `for i in a..b { body }` is a `while` over a counter the program cannot name, which steps before
  the body so that `continue` works:
  `{ let next = a; let end = b; while next < end { let i = next; next = next + 1; body } }`.
- `for k in m` over a map is `for k in keys(m)`: the compiler asks the builder for the type of `m`
  (`type_of`, `resolved_type`, `type_tag`) and wraps it when it is a map.
- `x += v` is `x = x + v`, with the target evaluated twice.
- `{"a": 1, "b": 2}` is a block that makes a map, sets each entry and yields the map.
- `o.name` on an `object` is the builtin `field(o, "name")`, which finds the field at run time.

## A rule of B0's own: `unsafe`

A0 offers raw pointers to any language (`ptr<T>`, `addr`, `offset`, `data`, indexing); B0 allows
them only inside `unsafe { ... }`. The walk counts the `unsafe` blocks around it and reports the
pointer builtins outside one, and indexing whatever already has a pointer type:

```rust
fn check_pointer_index(&mut self, operand: ExprId, node: NodeId) {
    let t = self.b.type_of(operand);
    let t = self.b.resolved_type(t);
    if self.unsafe_depth == 0 && self.b.module().type_tag(t) == TypeTag::Ptr {
        self.needs_unsafe(node, "indexing a raw pointer");
    }
}
```

The error uses A0's code `E2027` (`report_code`), so `b0 explain E2027` explains it and editors
show it like A0's own.

## A prelude written in the language

`map`, `filter`, `fold`, `each`, `any_of`, `range` and `sort` are B0 (`b0/src/prelude.b0`). `start`,
which the driver calls before compiling any file, compiles the prelude into a module of its own,
and every file imports from it the functions it does not declare itself:

```rust
pub fn compile_file(b: &mut HirBuilder, tree: &SyntaxTree) {
    let own = declared_functions(tree);
    for name in declared_functions(prelude()) {
        if !own.contains(&name) {
            b.import_item(PRELUDE_MODULE, name);
        }
    }
    ...
}
```

The prelude's source is registered as a built-in source (`a0_diag::register_builtin_source`), so
stack traces and the language server can point into it. Since the optimizer inlines small
functions and then the closures passed to them (D84), `fold(xs, 0, fn(a, b) { ... })` runs as fast
as the loop written out.

## Testing it

B0's tests are those every language here has, and they need little code:

- `tests/b0.rs` runs each program in `tests/programs`, whose comments say what it prints
  (`// expect: ...`, `// expect-stderr: ...`, `// expect-exit: ...`), interpreted, in the JIT,
  natively and under GC stress, each optimized and not: eight runs that must all agree.
- `tests/diagnostics.rs` compares each program in `tests/diagnostics` with the full output in its
  `.out` file, natively too; `A0_BLESS=1` rewrites them after a deliberate change.
- `tests/lsp.rs`, `tests/dap.rs` and `tests/repl.rs` drive the language server, the debugger and
  the REPL through the driver's test clients.
- `tests/packages.rs` builds a package with path and git dependencies; `tests/parallel.rs` checks
  that threads speed a program up; `tests/examples.rs` runs `examples/wordfreq`.

## What to take from it

Start from B0 (or from `a0 new`) and change the grammar first; keep the compiler a walk that
builds HIR by name, and let A0 report what is wrong. Add syntax by building HIR that exists; add a
rule A0 does not have in the walk, with one of A0's codes or your own (`Codes::Own`). Put library
code in the language itself where it can be, and test every program in every mode.
