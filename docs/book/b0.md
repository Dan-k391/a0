# Building a full language: B0

B0 is a complete statically typed language built on A0. It has structs, enums, generics,
interfaces, closures, maps, exceptions, threads, manual memory and calls to C. Its compiler is
about 1,350 lines of grammar and Rust, and it is written to be copied: when you start a large
language of your own, start from B0.

This chapter shows a B0 program, then walks through the compiler that runs it. It assumes you have
followed [the tutorial](../tutorial.md), which builds the same pieces for a small language.
[B0's guide](../../b0/README.md) describes the language itself.

## A B0 program

```
enum Shape { Circle(float), Rect(float, float) }

fn area(s: Shape) -> float {
  return match s { Circle(r) => 3.14159 * r * r, Rect(w, h) => w * h };
}

fn main() {
  let shapes = [Shape::Circle(1.0), Shape::Rect(2.0, 3.0)];
  let total = fold(shapes, 0.0, fn(sum: float, s: Shape) -> float { return sum + area(s); });
  print(total);
  let ages = {"Ada": 36, "Alan": 41};
  for name in ages {
    print(name + " is " + str(ages[name]));
  }
}
```

Save it as `shapes.b0` and run it:

```
$ b0 run shapes.b0
9.14159
Ada is 36
Alan is 41
```

`cargo build -p b0` in A0's repository builds the `b0` command into `target/debug`.

The program uses an enum whose variants carry values, a `match` that takes them apart, a closure
passed to `fold`, a map literal and a loop over the map's keys. `fold` is not built into B0: it is
a B0 function in B0's prelude, shown [below](#a-prelude-written-in-b0).

B0 has every command a language made with `a0 new` has ([getting
started](getting-started.md#what-your-language-can-do)). For example, `b0 build` makes an
executable that prints the same:

```
$ b0 build shapes.b0 -o shapes
$ ./shapes
9.14159
Ada is 36
Alan is 41
```

## How the compiler is organised

| File | What it is |
|---|---|
| `b0/b0.a0g` | the grammar: what B0 programs look like |
| `b0/src/lib.rs` | the compiler: one walk over the parsed program |
| `b0/src/prelude.b0` | the prelude: library functions written in B0, which every program sees |
| `b0/src/main.rs` | the `b0` command |
| `b0/tests/` | the tests |

A program goes through these pieces in order:

1. A0 parses the program with the grammar into a syntax tree.
2. The compiler walks the tree once. At each node it calls A0's *HIR builder*. The HIR, A0's
   high-level IR, is a typed form of the program that A0 knows how to run, compile and debug
   ([the high-level IR](../hir.md)).
3. The builder resolves names, infers and checks types, and reports errors. B0 has no symbol table
   and no type checker of its own.
4. A0 runs the finished HIR, or compiles it to an executable.

B0's crate depends on four of A0's crates and nothing else:

```toml
[dependencies]
a0-diag.workspace = true
a0-syntax.workspace = true
a0-hir.workspace = true
a0-driver.workspace = true
```

A0 promises not to break these crates before version 2.0 ([compatibility](../compatibility.md)).
The test `b0/tests/public_api.rs` fails if B0 ever uses another of A0's crates, so a language
copied from B0 stays on that promise too.

## The command

`b0/src/main.rs` is the whole `b0` command:

```rust
fn main() -> ExitCode {
    Language::new("b0", |text, source| match b0::compile(text, source) {
        Ok(m) => Ok(Program::Hir(m)),
        Err(d) => Err(CompileError::Diagnostics(d)),
    })
    .grammar(b0::GRAMMAR)
    .modules(Modules::new("b0", b0::start, b0::compile_file))
    .repl_main("fn main() {\n{}}\n")
    .main()
}
```

`Language` comes from `a0-driver`, which turns a compiler into a command with `run`, `build`,
`check`, `repl`, `lsp` and the rest. Each call adds something:

- **`Language::new`** names the language and gives the function that compiles a one-file program.
- **`grammar`** gives the language server the grammar. From it the server gets highlighting, the
  outline and navigation.
- **`modules`** turns on programs of several files and [packages](../packages.md). The driver
  finds a program's files through the grammar's `@import` rule. It calls `start` once to set up
  the builder, then `compile_file` on each file, each into a module of the same HIR builder.
- **`repl_main`** is the program the [REPL](../repl.md) puts the statements typed so far into,
  at `{}`.

## The grammar

`b0/b0.a0g` starts with the version of the grammar format and the tokens, then has one rule for
each part of a program. The rule for a function is:

```
grammar b0 version 1;
...
token INT /[0-9][0-9_]*/;
...
fn_decl @def(function) @scope
    = pub:"pub"? "fn" name:NAME ~ "expected a function name" type_params? "(" ~ "expected '('"
      (param ("," param)*)? ")" ~ "expected ')'" ("->" ret:type ~ "expected a type")?
      body:block ~ "expected '{'";
```

- `name:NAME` labels a part of the rule. The compiler finds the parts by these labels, which the
  grammar calls fields.
- `x ~ "message"` makes `x` required at that point. When it is missing, the parser reports the
  message.
- `@def(function)` says that the rule declares a function, named by its `name` field. `@scope`
  says that the rule opens a scope. These two are all the language server needs for the outline,
  go to definition, references and rename.

All of B0's operators are one `@prec` table, which lists them from the loosest to the tightest.
Every word that appears in the grammar as a literal is a keyword, and a keyword can never be a
name. That is why value structs are written `inline struct`: a keyword `value` would take a common
name away from programs. [Grammars](../grammar.md) explains the notation.

## Building HIR by name

The compiler builds HIR *by name*. It gives the builder the names it finds in the program, and the
builder works out what each name means in the scopes the compiler has opened. (A language that
resolves names itself, as Lox does, builds *by handle* instead: [the high-level
IR](../hir.md#building-hir-from-a-frontend) describes both.)

A `let` statement is compiled by this part of the walk:

```rust
"let_stmt" => {
    let value = self.expr(self.field(node, "value"));
    let ty = match self.opt(node, "type") {
        Some(t) => self.ty(t),
        None => self.b.fresh_type(),
    };
    let name = self.field(node, "name");
    self.at(name);
    if self.b.is_declared_in_scope(self.text(name)) {
        let msg = format!("`{}` is already declared in this scope", self.text(name));
        self.b.report_code(code::DUPLICATE, &msg);
        self.b.report_primary_label("declared again here");
        let first = self.b.lookup_local(self.text(name));
        if let Some(span) = first.and_then(|l| self.b.module().local_span(l)) {
            self.b.report_label(span, "first declared here");
        }
    }
    self.b.let_named(self.text(name), ty, value)
}
```

- `self.b` is the HIR builder.
- `fresh_type()` is a type for the builder to infer, used when the program writes none.
- `at(name)` makes what is built next point at the name in the source. A type error or an
  unused-variable warning about this `let` is then reported there.
- The `if` is a rule of B0's own: the HIR allows a name to be declared again in the same scope, and
  B0 does not. `report_code` reports it with A0's code for "declared twice", and `report_label`
  adds a second label at the first declaration.
- `let_named` declares the variable in the current scope.

Other names are built the same way:

| Builder function | For |
|---|---|
| `name(text)` | a variable or a function used as a value |
| `call_named(name, args)` | a call of a function by its name |
| `assign_named(name, value)` | an assignment to a variable |
| `field_named(object, name)` | a field of a struct |
| `method_call(receiver, name, args)` | a method call |
| `new_struct_named(s, names, values)` | a new struct, with its fields in any order |

Each one finds what the name means and checks it. It does this at once, or when the module is
finished and every type is known.

Items can be used before they are declared, because the compiler declares them before it compiles
any function body. `program` makes three passes over a file's items:

1. It declares every struct, enum and interface.
2. It adds their fields, variants and methods, and the signatures of functions.
3. It compiles the function bodies.

## Syntax that is not in the HIR

A language can have syntax the HIR has no form for: it builds the syntax out of forms the HIR has.
For example, this program loops over a range:

```
fn main() {
  for i in 0..3 {
    print(i);
  }
}
```

`b0 hir` prints the HIR that B0's compiler built. The `main` it prints is:

```
fn main() {
  {
    let next: int = 0;
    let end: int = 3;
    while next < end {
      let i: int = next;
      next = next + 1;
      {
        {
          print(i);
          print("\n");
        };
      };
    };
  };
}
```

The range became a `while` over a counter. The program cannot name the counter, since it is not
in any scope the compiler opened. The counter steps before the loop's body runs, so `continue`
works. `print(i)` became two prints, the value and a newline.

B0 builds the rest of its extra syntax the same way:

- **`for x in xs`** over an array is a `while` over an index.
- **`for k in m`** over a map is the loop over `keys(m)`. To tell a map from an array, the compiler
  asks the builder for the type of `m` (`type_of`, `resolved_type`, `type_tag`).
- **`x += v`** is `x = x + v`. The target is evaluated twice, so `a[f()] += 1` calls `f` twice.
- **`{"a": 1, "b": 2}`** is a block that makes a map, sets each entry and yields the map.
- **`o.name`** on a dynamic `object` is the builtin `field(o, "name")`, which finds the field at
  run time ([dynamic languages](dynamic.md)).

## A rule of B0's own: `unsafe`

A0 offers raw pointers to every language ([memory](memory.md)). B0 allows them only inside
`unsafe { ... }`:

```
fn main() {
  let nums = [1, 2, 3];
  let p = data(nums);
  print(nums[0]);
}
```

```
$ b0 check pointer.b0
error[E2027]: `data` needs `unsafe`
 --> pointer.b0:3:11
  |
3 |   let p = data(nums);
  |           ^^^^^^^^^^ unchecked
  |
  = help: raw pointers are unchecked: put this in an `unsafe { ... }` block
```

The walk counts the `unsafe` blocks it is inside. Outside all of them, it reports a call of `addr`,
`offset` or `data`, and indexing anything whose type is already known to be a pointer:

```rust
fn check_pointer_index(&mut self, operand: ExprId, node: NodeId) {
    let t = self.b.type_of(operand);
    let t = self.b.resolved_type(t);
    if self.unsafe_depth == 0 && self.b.module().type_tag(t) == TypeTag::Ptr {
        self.needs_unsafe(node, "indexing a raw pointer");
    }
}
```

The error uses A0's code `E2027`, so `b0 explain E2027` explains it and editors show it like any
of A0's errors. A language can report a problem with any code it likes; [diagnostics](../diagnostics.md)
explains codes and how a language shows them under its own names.

## A prelude written in B0

`map`, `filter`, `fold`, `each`, `any_of`, `range` and `sort` are written in B0, in
`b0/src/prelude.b0`. `fold` is:

```
pub fn fold<T, A>(xs: [T], init: A, f: fn(A, T) -> A) -> A {
  let acc = init;
  for x in xs {
    acc = f(acc, x);
  }
  return acc;
}
```

`start`, which the driver calls before it compiles any file, compiles the prelude into a module of
its own, `b0.prelude`. Each file then imports from that module every function the file does not
declare itself:

```rust
pub fn compile_file(b: &mut HirBuilder, tree: &SyntaxTree) {
    let own = declared_functions(tree);
    for name in declared_functions(prelude()) {
        if !own.contains(&name) {
            b.set_span(None);
            b.import_item(PRELUDE_MODULE, name);
        }
    }
    ...
}
```

So a program can declare its own `map`, and its `map` takes the place of the prelude's.

The prelude's source is registered with `a0_diag::register_builtin_source`. Stack traces and the
language server can then point into it, as `<b0>/prelude.b0`.

A prelude function costs little. A0's optimizer inlines small functions, and then inlines the
closures passed to them. So `fold(xs, 0, fn(a, b) { ... })` runs as a loop with the closure's body
in it ([performance](../benchmarks.md)).

## Testing it

B0 has the tests every example language in A0 has. Each needs little code, because the driver
provides the test clients:

| Test | What it checks |
|---|---|
| `tests/b0.rs` | each program in `tests/programs` prints what its comments say (`// expect: ...`, `// expect-stderr: ...`, `// expect-exit: ...`) |
| `tests/diagnostics.rs` | each program in `tests/diagnostics` prints exactly its `.out` file, natively too; `A0_BLESS=1` rewrites the files after a deliberate change |
| `tests/lsp.rs`, `tests/dap.rs`, `tests/repl.rs` | the language server, the debugger and the REPL |
| `tests/packages.rs` | a package with a path dependency and a git dependency, and its lock file |
| `tests/parallel.rs` | threads make a program faster |
| `tests/examples.rs` | the program in `examples/wordfreq` |
| `tests/fuzz.rs` | the compiler never crashes on mutated programs |
| `tests/public_api.rs` | B0 uses only the crates A0's compatibility promise covers |

`tests/b0.rs` runs each program eight ways, and all eight must agree:

- interpreted, in the JIT (compiled to machine code in memory), in the JIT with the collector
  running at every allocation, and as an executable;
- each of those with A0's optimizer on and off.

## What to take from it

- Start from B0, or from `a0 new`, and change the grammar first.
- Keep the compiler one walk that builds HIR by name, and let A0 find what is wrong.
- Add syntax by building it from HIR forms that exist.
- Add a rule A0 does not have, such as `unsafe`, in the walk, and report it with a code.
- Write library code in the language itself where you can.
- Test every program in every mode.
